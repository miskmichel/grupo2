## `splits/`

The train/test split, materialised once so it cannot drift.

| File | Contents |
|---|---|
| `train.csv` | 5634 rows — cleaned features + `Churn`, indexed by `row_id` |
| `test.csv` | 1409 rows — **held out**, do not read until final evaluation |
| `customer_ids.csv` | `row_id → customerID`, for re-attaching predictions |
| `manifest.json` | Generation parameters + SHA-256 of each file |

Generated by `src/make_splits.py`, stratified on `Churn` at `random_state=42`,
80/20. Both folds hold the 26.54% churn rate to within 0.007 pp.

**Load them with `data_prep.load_splits()`, not by re-splitting.** Three people
training in parallel must score on the same held-out rows or the comparison
table is meaningless.

```bash
python3 src/make_splits.py --check   # verify on-disk files match the manifest
python3 src/make_splits.py           # regenerate (invalidates every prior score)
```

Regenerating changes the row assignment only if the cleaning or parameters
changed — but if it does, **every score recorded before that point becomes
incomparable.** Say so loudly if you regenerate.
